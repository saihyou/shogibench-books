# shogibench-books

将棋エンジンのテスト対局に使う開始局面集です。

各アーカイブは**単一のファイル**を含みます。表の sha256 は zip ではなく
**展開後のファイル**に対する値です。

| ファイル | 中身 | 局面数 | 展開後の sha256 |
| --- | --- | --- | --- |
| `floodgate_2015_2026_36_balanced.sfen.zip` | `floodgate_2015_2026_36_balanced.sfen` | 30,000 | `e6674478e767eb9263517e8432b2f7454f6bf4339f91edba6b550d83239b0bff` |
| `floodgate_2015_2026_36_unbalanced.sfen.zip` | `floodgate_2015_2026_36_unbalanced.sfen` | 30,000 | `6b1ec8fdd024c88bcc2ab9d8cfd6d4be42a448df2eecca7cdb6df084c830f678` |
| `nyugyoku_entered.sfen.zip` | `nyugyoku_entered.sfen` | 10,000 | `e72a70ecf96807c67d35dca95db9c4040457db64e64fe08b71e463f056963d00` |
| `nyugyoku_aiming.sfen.zip` | `nyugyoku_aiming.sfen` | 8,244 | `7c4b830493cdbfec48f6f51117bb6227aee438211f18454f2e75e454705ba934` |

1行1局面で、`startpos moves ...` / `sfen ... [moves ...]` / 素の SFEN の
いずれかの形式です。
floodgate 局面集は `startpos moves ...`、入玉局面集は素の SFEN です。

## floodgate 局面集について

[floodgate](https://wdoor.c.u-tokyo.ac.jp/shogi/) の棋譜 (年ごとに公開されている
アーカイブ) の 2015-2026 年分、1,223,794 局から作りました。各対局の 36手目
(18手ずつ) の局面を候補にし、エンジンで評価して評価値で絞り込んでいます。

- `balanced` — 評価値の絶対値が 100 以下。互角の局面
- `unbalanced` — 評価値の絶対値が 200 から 400。片方に小さな有利がある局面
  (チェスの UHO 相当)

**どちらも 30,000 局面すべてが異なる局面です。** 手順前後で同じ局面に合流する
棋譜が多いため、指し手列ではなく到達局面で重複を除いています。同じ開始局面から
先後を入れ替えて2局指すので、30,000 局面で 60,000 局まで重複なく回せます。

不均衡な局面を使うのは、有利が先後の入れ替えで両者に等しく配分され、残るのが
エンジンの差だけになるためです。引き分け (千日手) が減るぶん1局あたりの情報量が
増え、SPRT も SPSA も速く収束します。

並び順はシードつきで混ぜてあります。対局ツールは局面集を先頭から順に使い、自分
ではシャッフルしないので、そのままだと対局数が局面数より少ないときに戦型が偏る
ためです。

### 作りかた

1. 年ごとに公開されているアーカイブから CSA を取得する (2015-2026年、
   1,223,794 局)
2. 各対局の36手目までを `startpos moves ...` の形で取り出す。指し手は実際に
   並べ直して合法性を確かめ、決着済みの局面は捨てる
3. 両対局者のレーティングが、その年の中央値以上の対局だけを使う。floodgate の
   レーティングは年々インフレしていて、両対局者の低いほうの中央値は2015年が
   2518、2026年が 3336。固定のしきい値だと古い年がまるごと落ちる
4. 到達局面で重複を除く。手順前後で同じ局面に合流する棋譜が多く、指し手列で
   見ると3割前後を取りこぼす。ここで 463,017 局 → 282,863 局面
5. 各局面をエンジンで 500,000 ノード探索して評価値をつける。詰み絡みは捨てる
6. 評価値の絶対値で絞り込み、シードつきで並べ替えて 30,000 局面を取る

## 入玉局面集について

入玉模様の将棋を集中的にテストするための局面集です。序盤の開始局面集と違い、
中盤から終盤の局面を**素の SFEN** (指し手なし) で収めています。手数はすべて
`1` に揃えてあり、先手番と後手番が半々ほど含まれます。

- `entered` — どちらかの玉 (または両方) が**すでに敵陣** (先手玉なら 1-3段目、
  後手玉なら 7-9段目) にいる局面。約半数は両方の玉が敵陣に入っています
- `aiming` — どちらかの玉が**敵陣の一歩手前** (先手玉なら 4段目、後手玉なら
  6段目) にいて、入玉を狙える局面。相手玉が先に敵陣へ入っている局面も含みます

どちらも王手がかかっている局面と、入玉宣言がすでに成立している局面は含みません。
各ファイルの中で局面はすべて異なります。片方の玉が敵陣に入り、もう片方が一歩手前
という局面は両方の条件を満たすため、2つのファイルには 799 局面の重複があります。
両方を続けて使う場合はその分だけ局面が重なります。

通常の開始局面集と同じく、同じ局面から先後を入れ替えて2局指す使いかたを想定して
います。入玉形は評価関数の不得手な領域になりやすく、通常の対局ではめったに現れない
ため、こうした局面を開始局面にして入玉関連の変更を直接比較します。

## 改行コードは LF

ファイルを**テキストモードで読んで** sha256 を計算する処理系では、CRLF が
読み込み時に LF へ変換され、`sha256sum` で得た値と食い違います。LF に揃えて
あるので、どちらの読みかたでも上の表の値と一致します。
